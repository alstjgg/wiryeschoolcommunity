## 1. 기관 개요

### 1.1 위례인생학교란?

위례인생학교는 성인을 대상으로 하는 평생교육 프로그램이다. 다양한 분야의 강좌를 제공하며, 지역 주민들의 평생 학습을 지원한다.

### 1.2 운영 주체

- **운영**: 위례인생학교 사무처 (관리자 2~4명)
- **플랫폼**: 배움숲 (수강신청 포털)
- **홍보**: 네이버 카페

## 2. 회차 구조

### 2.1 회차제

연 4회차 운영. 각 회차는 3개월, 강좌당 최대 12회차.

| 회차 | 계절 | 시작월 | 기간 |
|:---:|:----:|:-----:|:----:|
| 1 | 겨울 | 1월 | 1월 ~ 3월 |
| 2 | 봄 | 4월 | 4월 ~ 6월 |
| 3 | 여름 | 7월 | 7월 ~ 9월 |
| 4 | 가을 | 10월 | 10월 ~ 12월 |

회차 식별자: `{연도}-{번호}` (예: `2026-1`)
회차명: `{연도}-{번호} {계절}학기` (예: `2026-1 겨울학기`)

### 2.2 주요 업무 일정

| 시점 | 업무 |
|-----|------|
| 학기 시작 2달 전 | 강사에게 강의 계획서 요청 |
| 학기 시작 1달 전 | 강의 계획서 검토, 배움숲/카페 홍보 게시 |
| 전월 말일까지 | 수강신청 접수 마감 |
| 개강 첫 주 전 토요일 | 강사에게 수강자 목록(출석부) 전달 |
| 개강 1주 후 | 환불 마감 |
| 학기 종료 후 | 출석 체크(OCR), 종강 처리, 운영 보고서 작성 |

## 3. 회원 등급 체계

### 3.1 등급 구조

3단계 등급 구조. 승급/강등이 회차 흐름과 입금 상태에 따라 전환된다.

```
[비회원] ──가입비──→ [회원] ──수강료 입금──→ [준회원] ──종강──→ [회원]
                       │
                       └──정회원비──→ [정회원] ──후년1학기(겨울) 종강──→ [회원]
```

| 등급 | 승급 조건 | 수강 신청 | 수강료 | 유효기간 | 만료 시 |
|------|---------|:--------:|:------:|---------|--------|
| 회원 | 가입비 납부 | 가능 | 필요 | 영속 | — |
| 준회원 | 수강료 입금 완료 (1과목 이상) | 등록 완료 | 납부 완료 | 해당 회차 종강까지 | 회원으로 강등 |
| 정회원 | 정회원비 납부 | 가능 | **면제** | ~후년 1학기(겨울) 종강까지 | 회원으로 강등 |

비회원은 시스템 외부 상태이며, 가입비 납부 완료 시 회원으로 등록된다.

### 3.2 등급 전환 시점

| 시점 | 전환 내용 |
|------|----------|
| 가입비 납부 완료 | 비회원 → 회원 |
| 수강료 입금 확인 (1과목 이상) | 회원 → 준회원 |
| 정회원비 납부 | 회원 → 정회원 |
| 회차 종강 | 준회원 → 회원 |
| 1학기(겨울) 종강 | 정회원 → 회원 (강사/사무처 직원 예외) |

### 3.3 특수 케이스

- **강사**: 자동으로 정회원 자격 부여. 1학기 종강 시 일괄 강등에서 제외.
- **사무처 직원**: 입사 시 정회원으로 승격. 퇴사 시 해당 회차까지 유지. 1학기 종강 시 일괄 강등에서 제외.

### 3.4 등급 전환 자동화 (Grade Cascade)

입금 대조 시 `apply_grade_cascade()` 함수가 자동 실행. Idempotent (재실행 가능).

3-Pass 순서:
1. **신규가입 confirmed** → 비회원을 회원으로 등록
2. **정회원 confirmed** → 회원을 정회원으로 승급 (회원이 아니면 🔶확인필요)
3. **수강** → 정회원이면 💎면제, 정회원비 미입금이면 🔶확인필요, 확정이면 준회원 승급

### 3.5 정회원 수강 등록 처리

정회원은 수강료가 면제이므로, 수강 신청만으로 등록이 완료된다.
Grade cascade의 Pass 3에서 자동으로 입금현황 = "💎면제"로 설정.

## 4. 비용 구조

### 4.1 비용 항목

| 항목 | 기본 금액 | 비고 |
|------|:--------:|------|
| 가입비 | 1만원 | 신규 회원 가입 시. 변동 가능 |
| 수강료 | 2만원 | 전 과목 동일. 변동 가능 |
| 정회원비 | 12만원 | 매년 초(약 2월) 결정. 변동 |

### 4.2 입금 패턴

입금자가 은행 적요란에 자유롭게 입력하므로, 형식이 통일되어 있지 않다.

| 케이스 | 설명 | 금액 |
|-------|------|:----:|
| 기본 | 단일 과목 수강료 | 2만원 |
| 신규 (별도) | 가입비 + 수강료 각각 입금 | 1만원 + 2만원 |
| 신규 (합산) | 가입비 + 수강료 합산 입금 | 3만원 |
| 다과목 (별도) | 과목별 각각 입금 | 2만원 × N |
| 다과목 (합산) | 여러 과목 합산 입금 | 2만원 × N |
| 정회원비 | 정회원 가입 | 12만원 |
| 가입비+정회원비 (합산) | 신규 가입 + 정회원 동시 | 13만원 |
| 중복 | 동일 건 중복 입금 | 환불 처리 필요 |
| 대리 입금 | 가족 등이 대신 입금 | 적요와 의뢰인 불일치 |

### 4.3 환불

- **개강 전**: 전액 환불 가능
- **개강 1주 후**: 환불 불가
- **처리**: 별도 민원 담당자가 처리

## 6. 수강 등록

### 6.1 입금현황 코드 (6가지)

| 코드 | 이모지 | 의미 |
|-----|:-----:|------|
| confirmed | ✅ | 정상 매칭 |
| needs_review | 🔶 | 확인 필요 (LLM 추정, 동명이인, 금액 불일치 등) |
| name_mismatch | ⚠️ | 이름 불일치 (대리 입금 추정) |
| not_paid | ❌ | 미입금 |
| duplicate | 🔄 | 중복 입금 |
| exempted | 💎 | 정회원 — 수강료 면제 |

DB에는 코드(`confirmed` 등)로 저장. Sheets에는 n8n Code 노드에서 이모지로 변환하여 표시.

### 6.2 처리상태 (신규)

관리자가 Sheets에서 직접 입력하는 드롭다운. 신청기록 시트와 미확인입금 시트 양쪽에 존재.

| 값 | 의미 | 출석부 생성 가능? |
|---|---|:---:|
| `등록완료` | 정상 처리 완료 (배움숲 등록 등) | ✅ |
| `환불완료` | 환불 처리 완료 | ✅ |
| `취소완료` | 신청 취소 (미등록) | ✅ |
| `보류` | 확인 중, 아직 결정 안 됨 | ❌ |
| 빈칸 (미입력) | 아직 확인하지 않음 | ❌ |

**Gate 조건**: 신청기록 + 미확인입금 양쪽 모두 처리상태가 NULL 또는 보류인 건이 0일 때만 출석부 생성 등 다음 작업으로 진행 가능.

### 6.3 입금 대조

은행 입금내역과 수강 신청 목록을 비교하여 입금 상태를 판정하는 핵심 업무이다.

**처리 방식**: 코드 기반 규칙 매칭(80~90%) + LLM 기반 예외 처리(10~20%)

**전체 플로우**:
1. 관리자: "입금 대조" 클릭 → 회차 확인
2. 관리자: 신청자 엑셀 업로드 → 통합 신청서 생성 (수강 + 신규가입 + 정회원 → DB applications)
3. 관리자: 입금내역 엑셀 업로드 → 전건 DB deposits INSERT
4. Agent: 자동 매칭 (코드 80~90% → LLM 10~20%)
5. Agent: 등급 전환 cascade 실행 (신규가입 → 정회원 → 수강)
6. Agent: 결과 요약 + n8n webhook (Sheets push) + 미확인입금 안내
7. 관리자: 신청기록/미확인입금 시트에서 확인 → 처리상태 입력
8. 관리자: "입금 대조 재실행" 가능 (cascade idempotent)
9. 모든 처리상태 입력 완료 후 → "출석부 생성" 진행

## 7. 강의 관리

### 7.1 강의 계획서

강사가 매 학기 강의 계획서를 제출한다.

**파일 형식**: PDF만 지원 (HWP 미지원)

**AI 처리**:
- 1순위: 오탈자 수정, 말투 수정, 배움숲 업로드용 카테고리별 복붙 멘트 생성
- 후순위: 내용 보강, 용어 보완, 네이버 카페 멘트 생성

### 7.2 출석 관리

**출석부 구조**: Google Sheets 1개 파일, 과목별 시트탭. 각 시트: ID, 이름, 1회차~12회차, 출석률.

- 강좌당 최대 12회차로 구성
- 출석률 = 출석수 / 회차수 × 100
- 처리상태 "등록완료"인 수강자만 출석부에 포함
- 과목별 PDF도 생성 (A4 프린트용)

**출석 체크(OCR)**: 실물 출석부에 체크/사인으로 회차마다 출석 확인 후, 종강 이후 강좌별 1회씩 출석부 사진을 촬영하여 AI(Claude Vision)로 디지털화한다.

### 7.3 휴강/보강

- 강사가 직접 처리
- 처리 후 사무처에 알림

## 8. 데이터 구조

### 8.1 데이터 아키텍처

Dual-Write 모드 (`USE_DB_SOT` 환경변수로 전환):
- `USE_DB_SOT=true`: PostgreSQL이 SoT. 챗봇은 DB에서 읽고 DB+Sheets에 동시 쓰기. n8n이 DB→Sheets 동기화.
- `USE_DB_SOT=false` (기본): Google Sheets가 SoT. 기존 동작 유지.

DB 실패 시 자동 폴백: Sheets로 전환 + 로그 기록. 서비스 중단 없음.

| 계층 | 성격 | DB 테이블 | Sheets 탭 |
|------|------|-----------|-----------|
| **Master** | 현재 상태 스냅샷 | `members` | 회원관리 → 회원목록 |
| **History** | 이력 (append-only) | `member_records`, `course_records` | 회원관리 → 회원기록, 수강기록 |
| **Working** | 전 회차 누적 | `applications`, `deposits` | 회원관리 → 신청기록, 미확인입금 |
| **Working** | 회차별 | `attendance` | 회차폴더 → 출석부 |
| **Raw** | 외부 원본 | — | Google Drive / 챗봇 업로드 |

**DB → Sheets 동기화** (n8n):
- Sync-1: 매일 06:00 KST 전체 push (5탭 덮어쓰기)
- Sync-2: 챗봇 웹훅 즉시 push (변경 시트만)

## 10. 용어 정리

| 용어 | 설명 |
|-----|------|
| 회차 | 연 4회 운영 단위. 식별자: `2026-1` |
| 회차명 | 표시용 이름. `2026-1 겨울학기` |
| 이름ID | 사용자 식별자. `이름+핸드폰뒤4자리` (예: 박민서6804) |
| 회원 | 가입비 납부 완료. 수강 신청 자격. 영속 |
| 준회원 | 수강료 입금 완료 회원. 해당 회차 종강까지 유효 |
| 정회원 | 정회원비 납부 회원. 수강료 면제. 후년 1학기(겨울) 종강까지 유효 |
| 배움숲 | 수강신청 포털 사이트 |
| 신청자 목록 | 배움숲에서 다운로드한 수강 신청자 엑셀 (LEARNING_APPLY*.xls) |
| 가입비 | 신규 회원 가입 시 납부 비용 (기본 1만원, 변동 가능) |
| 수강료 | 강좌 수강을 위해 납부하는 비용 (기본 2만원, 변동 가능) |
| 정회원비 | 정회원 가입 비용 (기본 12만원, 매년 초 결정, 변동) |
| 개강 | 해당 회차 첫 수업 시작 |
| 종강 | 해당 회차 마지막 수업 종료 |
| 입금 대조 | 은행 입금내역과 수강 신청 목록을 비교하여 입금 상태를 판정하는 업무 |
| 출석 체크 | 종강 후 실물 출석부를 사진 촬영하여 AI(OCR)로 디지털화하는 업무 |
| 종강 처리 | 회차 종료 후 출석률 계산, 등급 강등, 수강기록 추가, 보고서 작성 등 일괄 처리 |
| 처리상태 | 관리자가 Sheets에서 직접 입력하는 드롭다운 (등록완료/환불완료/취소완료/보류) |
| 신청기록 | 전 회차 누적 통합 신청서 (수강+신규가입+정회원). 회원관리 파일의 탭 |
| 미확인입금 | 자동 매칭 안 된 입금 건. 회원관리 파일의 탭 |
| Grade Cascade | 입금 대조 시 등급 전환을 순서대로 자동 적용하는 함수 (idempotent) |
